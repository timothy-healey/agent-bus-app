## Parallel flow (fork/join)

- [x] **P1 · Nested groups / non-linear lanes** — `done` (tag `plan-p1-nested-groups`) — lifts the flat-linear-lane restriction: a fork lane may now contain a **gate** and/or a **nested fork** (a child `FanOutGroup`). `FanOutGroup` is **recursive** via an optional parent link — `parent_group_id` + `parent_lane` (migration `008_nested_groups.sql`, two nullable columns on `fanout_groups`; append-only, 001–007 untouched; registered in BOTH `app/src/lib.rs` migration lists + the `user_version` test bumped 7→8). A nested fork inside a lane expands (the same `expand_fork` path as a top-level fork) into a **child group** carrying the enclosing group id + lane; when the child group's barrier completes, its continuation is mapped to a **parent-lane verdict** (`FanOutGroup::parent_lane_verdict`: downstream ⇒ approve, needs-human ⇒ reject) and recorded at the **parent group's barrier** via the SAME `record_and_try_complete`/quorum/early-cancel methods — the SAME `UPDATE fanout_groups SET completed=1 WHERE id=? AND completed=0` single-writer guard, one level up. **Exactly-once-completion is preserved per group row, independently at every level**: child-complete and parent-settle are deliberately SEPARATE single-row-guarded writes (reference by id, no cross-root transaction); a concurrent-straggler test proves exactly-once at the nested level. The lane-walk is hierarchical in BOTH the runtime (`lane_reaches`: team→on_approve, gate→downstream, fork→nested join's downstream) and validation (`check_lane_reachable` replaces `check_lane_linear`), bounded at **max nesting depth 3** (`NestingTooDeep`); best-effort validation drops the old no-gate-in-a-lane rule. Flat lanes + P2 early-cancel + P3 quorum paths unchanged (root groups carry `parent=None` and spawn the continuation as before). **Backend-heavy — no frontend surface** (nested lanes do not yet render distinctly in PipelineView; a hierarchical viewer is deferred to the impeccable pass alongside the deferred P2/P3 authoring controls). - [x] **P2 · Early-cancel on first reject** — `done` (tag `plan-p2-early-cancel`) — opt-in per-join `Join.cancel_on_reject` (`#[serde(default)]` false; additive, **no `SCHEMA_VERSION` bump** — still 2). When a lane settles as a failure (reject / revise-cap) on a `cancel_on_reject` join, the `FanOutGroup` completes to **needs-human IMMEDIATELY** via the SAME `UPDATE fanout_groups SET completed=1 WHERE id=? AND completed=0` single-writer guard the full barrier uses — exactly-once-completion preserved (incl. a concurrent straggler-settle). The early-cancel aggregation rule lives on the aggregate root (`FanOutGroup::early_cancel_continuation`); the store's `record_failure_and_early_cancel` asks for it after winning the guard. Outstanding not-yet-finished lane tasks are parked via `TaskStore::cancel_outstanding_lanes` (`queued`/`revising` → `done` at their `join_target`) so queued workers don't claim+run them; a `running` lane is left to finish (never kill a live subprocess) and its later settle no-ops on the completed guard. - [x] **P3 · Quorum joins (N-of-M)** — `done` (tag `plan-p3-quorum-joins`) — opt-in per-join `Join.quorum: Option<u32>` (`#[serde(default, skip_serializing_if)]` None = all-must-approve, the unchanged default; additive, **no `SCHEMA_VERSION` bump** — still 2). When set, the `FanOutGroup` aggregate resolves the barrier as soon as **N of M lanes approve** (`quorum_continuation` early-resolves to `downstream`); if reaching N becomes impossible (unsettled lanes + approvals-so-far < N) it resolves to **needs-human** immediately; otherwise it parks. AND completed=0` single-writer guard, so **exactly-once-completion is preserved** under concurrent settles + stragglers. Once resolved, outstanding lanes are parked via P2's `cancel_outstanding_lanes` (queued/revising → done; a running lane finishes and its later settle no-ops on the guard). Validation: `quorum` (if set) must be `1..=waits_for.len()` (`QuorumOutOfRange`). **Interplay (DD7):** when a quorum is set it **governs success and `cancel_on_reject` is ignored** — a reject only counts as a non-approval that can make quorum impossible; default joins (None) keep honoring `cancel_on_reject` exactly as P2 shipped. Frontend: `quorum?: number` on the `Join` IPC type (round-trips through load/save); a **wizard authoring control is deferred to the impeccable pass** (pair with the deferred P2 `cancel_on_reject` toggle).
