- [x] **G1 · Stores as first-class nodes on the canvas** — `done` (tag plan-B4) (LF9) — the bounded-buffer stores (`Team.store.capacity`) are invisible on the authoring graph today (`draftToFlow` only emits node→node edges). Render each team's bounded **input store** as a distinct **store node** between the producer and the team: `research ──▶ [store ▢▢▢ /3] ──▶ spec-writers`. Capacity edited on the store node's drawer; live occupancy already surfaces on the board (④e). Add a `store` entry to the NodeKind-driven palette/renderer/node-drawer (F9 extensibility). **Open at spec time:** whether the store is a derived/synthetic canvas node projected from `Team.store` (no model change) or a real new `NodeKind` (model change) — lean derived-from-`Team.store` to avoid a schema bump. Touches `draftFlow.ts` (emit store nodes + reroute edges through them), `layout.ts`, `canvas/nodes/*`, `NodeDrawer`.
- [x] **G2 · Legible reviewer outcomes + decline semantics** — `done` (tag plan-B4) (LF1) — revise/reject edges already render (dashed purple/red, animated) but read as anonymous dashed lines. Make a reviewer's three outcomes obvious: **label** edges by outcome (approve / revise / decline), curve the **revise** edge as an explicit loop back to the writer, and ensure **decline (reject)** always terminates at a **needs-human / hand-off** node — the engine escalates a reviewer reject (`apply_gate_verdict`/`resolve_join_barrier`), so the canvas must show where declined work goes. Add a best-effort validation warning when a reviewer has no revise or no decline route. Touches `draftFlow.ts`/`pipelineGraph.ts` edge vocab + `PipelineCanvas` edge styling + `best_effort_validate` badges.
- [x] **G3 · Generate produces well-formed review structures** — `done` (tag plan-B5) (LF2) — "auto graph mostly produced implementation nodes." Root cause is upstream of layout: the design-session **Generate** (slice schema/prompt) under-produces reviewer nodes + their revise/decline routes, so reviews arrive under-connected (`teamRole`'s regex *can* classify `…-reviewers`, so layout/role inference is not the cause). Strengthen the kickoff generation so recommended graphs include reviewer teams with `role: reviewer` set explicitly + their approve/revise/decline routes wired. Touches `pipeline/src/design_session.rs` (the slice schema/prompt) — pairs with N-NativeToolUse for the forced-schema path. Note: also have Generate set `Team.role` explicitly (today it likely relies on the name regex).

## Discovery & prefill follow-ups (from live test 2026-06-25 — cluster C2)

> Source: `docs/live-test-findings-2026-06-25.md` (LF6/LF8), investigated 2026-06-25. Root causes confirmed in code.

- [x] **G4 · Skills available during project creation** — `done` (tag plan-B5) (LF6) — the prompt autocomplete shows no skills *during creation* because (a) the wizard's `PipelineCanvas` is rendered with **no `skills` prop** (`NewProjectWizard.tsx:152` — only `PipelineEditor` passes the catalog), and (b) `useSkillCatalog(projectId)` short-circuits to empty when `projectId` is null (no project exists yet mid-creation), so the global `~/.claude` catalog never loads. Fix: pass a catalog to the wizard canvas, and make `list_skills`/`useSkillCatalog` resolve the **global `~/.claude` roots even with no project** (`project_id` optional → global-only; project sources merged in once a project exists). Touches `NewProjectWizard`, `useSkillCatalog`, `list_skills` (accept null project).
- [x] **G5 · Generate prompt bodies + per-node regenerate** — `done` (tag plan-B5) (LF6) — a regression: the kickoff `Generate` emits a **teams slice only**; prompt *bodies* were produced by the per-step **Prompts** design-session step (`Step::Prompts`/`PromptSlice`), which was removed when the graph-builder dropped per-step chat — so prompts are never prefilled now. Fix: extend the kickoff one-shot to emit a `prompt_body` per team (teams + prompts in one Generate) so the canvas/node-drawer is prefilled, AND re-introduce per-team prompt generation as a per-node **"regenerate prompt"** affordance in the node drawer (the `Step::Prompts`/`PromptSlice` logic still exists behind the `llm_chat` seam). Touches `pipeline/src/design_session.rs` (kickoff includes prompts), `NodeDrawer` (regenerate button). Pairs with G3.
- [x] **G6 · Model selector + availability handling** — `done` (tag plan-B3) (LF8) — replace the free-text model input with a **curated selector** of known current Claude model IDs (+ a free-text override flagged "unverified"). There is no subscription model-list API, so no false pre-validation; instead handle unavailability where it fails: (a) the runner **detects a "model not found/unavailable" error and classifies it distinctly**, surfaced as a clear "model unavailable — pick another" on the card (no silent generic failure; dovetails with L3 failure detail), and (b) a **"Test model" probe** button in the node drawer fires a 1-token call to confirm at authoring time. Touches `NodeDrawer` (selector + probe), `runners` (classify model-unavailable), card error detail.
