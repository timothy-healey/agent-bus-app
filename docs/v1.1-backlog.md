## Parallel flow (fork/join)

- [ ] **P1 · Nested groups / non-linear lanes** — v1 lanes are flat-linear (no gates or nested forks inside a lane); make `FanOutGroup` recursive + the lane-walk hierarchical (the `completed`-guard barrier generalises unchanged). Source: `plan-parallel-flow.md` D8/D10.
- [x] **P2 · Early-cancel on first reject** — `done` (tag `plan-p2-early-cancel`) — opt-in per-join `Join.cancel_on_reject` (`#[serde(default)]` false; additive, **no `SCHEMA_VERSION` bump** — still 2). When a lane settles as a failure (reject / revise-cap) on a `cancel_on_reject` join, the `FanOutGroup` completes to **needs-human IMMEDIATELY** via the SAME `UPDATE fanout_groups SET completed=1 WHERE id=? AND completed=0` single-writer guard the full barrier uses — exactly-once-completion preserved (incl. a concurrent straggler-settle). The early-cancel aggregation rule lives on the aggregate root (`FanOutGroup::early_cancel_continuation`); the store's `record_failure_and_early_cancel` asks for it after winning the guard. Outstanding not-yet-finished lane tasks are parked via `TaskStore::cancel_outstanding_lanes` (`queued`/`revising` → `done` at their `join_target`) so queued workers don't claim+run them; a `running` lane is left to finish (never kill a live subprocess) and its later settle no-ops on the completed guard. New `(queued, done)`/`(revising, done)` early-cancel-park edges are explicit in the Task state machine. Default joins keep the full-barrier path unchanged. Frontend: `cancel_on_reject?: boolean` on the `Join` IPC type (round-trips through load/save); a wizard authoring toggle is deferred to the impeccable pass. DDD vet `docs/vet-p2-early-cancel-2026-06-23.md` (SOUND WITH FIXES — F1 aggregate-owns-the-rule, F2 state-machine-edges-explicit, F3 DOMAIN.md+spec; all applied). Source: parallel-flow plan Roadmap.
- [x] **P3 · Quorum joins (N-of-M)** — `done` (tag `plan-p3-quorum-joins`) — opt-in per-join `Join.quorum: Option<u32>` (`#[serde(default, skip_serializing_if)]` None = all-must-approve, the unchanged default; additive, **no `SCHEMA_VERSION` bump** — still 2). When set, the `FanOutGroup` aggregate resolves the barrier as soon as **N of M lanes approve** (`quorum_continuation` early-resolves to `downstream`); if reaching N becomes impossible (unsettled lanes + approvals-so-far < N) it resolves to **needs-human** immediately; otherwise it parks. The aggregate owns the rule; the store's new `record_and_try_quorum` drives it behind the SAME `UPDATE fanout_groups SET completed=1 WHERE id=? AND completed=0` single-writer guard, so **exactly-once-completion is preserved** under concurrent settles + stragglers. Once resolved, outstanding lanes are parked via P2's `cancel_outstanding_lanes` (queued/revising → done; a running lane finishes and its later settle no-ops on the guard). Validation: `quorum` (if set) must be `1..=waits_for.len()` (`QuorumOutOfRange`). **Interplay (DD7):** when a quorum is set it **governs success and `cancel_on_reject` is ignored** — a reject only counts as a non-approval that can make quorum impossible; default joins (None) keep honoring `cancel_on_reject` exactly as P2 shipped. Frontend: `quorum?: number` on the `Join` IPC type (round-trips through load/save); a **wizard authoring control is deferred to the impeccable pass** (pair with the deferred P2 `cancel_on_reject` toggle). DDD vet `docs/vet-p3-quorum-joins-2026-06-23.md` (SOUND WITH FIXES — F1 Join-language softened, F2 aggregate precondition doc-comment, F3 pool-owns-precedence confirmed; all applied). Source: parallel-flow brainstorm (considered, deferred).
