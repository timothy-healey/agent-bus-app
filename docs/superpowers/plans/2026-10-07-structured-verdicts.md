# Structured Verdicts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every worker returns its items, artifact and verdict as schema-validated **Structured output** (`claude --json-schema`), a reviewer's verdict carries a reason that reaches the producer, and the engine acts on reviewer verdicts on every edge.

**Architecture:**
- The kernel (`agent_bus_core`) gains the output types (`GeneratorOutput`, `ProducerOutput`, `ReviewerOutput`), `OutputKind` (with `schema()`, generated once through schemars) and `WorkerResult`.
- The Runners ACL is the only code that knows `--json-schema` and `result.structured_output`. `RunnerOutput` carries `result: WorkerResult`; a missing or mis-shaped object is `RunnerError::NoStructuredOutput`. The marker parsers are deleted.
- Runtime takes items from `WorkerResult`, writes a `review` comment for every reviewer result through a Runtime-local writer seam, routes reviewer verdicts on plain edges through helpers shared with `apply_gate_verdict`, and reads the revision bundle across the item's lineage `(run_id, item_key)`.
- The app wires the SQLite reader and writer; the frontend labels review comments.

**Tech Stack:** Rust (Tauri 2, sqlx/SQLite, serde, schemars 0.8), React 18 + TypeScript, vitest.

**Spec:** `docs/superpowers/specs/2026-10-07-structured-verdicts-design.md`
**Research:** `docs/research/json-schema-print-stream.md` on branch `research/json-schema-print`

## Global Constraints

- Argv: `--json-schema=<compact JSON>` as ONE element (the `=` form); the user message stays the last positional element.
- Source of truth: `result.structured_output` on the final `result` event. Its absence (even with `subtype: success`, exit 0) or a failed deserialise is `RunnerError::NoStructuredOutput { detail }`.
- Schemas: generated by schemars with `option_add_null_type = false`, `inline_subschemas = true`, `meta_schema = None`. Only `string` / `enum` / `array` / `object` types; no `$ref`, no `null`.
- Generator `{ items: [{ key, description, artifact? }] }`; producer `{ artifact?, description? }`; reviewer `{ verdict: approve|revise|reject, reason, artifact? }` (`reason` required).
- Output kind per stage: source → Generator; reviewer role → Reviewer; otherwise Producer.
- `scope.rs` always allows `StructuredOutput`.
- Audit error class string: `error:no_structured_output` (matches the existing snake_case classes the frontend reads).
- Review comment: `kind = 'review'`, `task_id` = the reviewed task, `artifact_path` = the reviewed artifact (`parent_artifact`, `""` when none), `note` = `"<team>: <verdict>. <reason>"` (no em dash: PRODUCT/DESIGN copy rule).
- Revision bundle: comments joined to tasks by `(run_id, item_key)`, oldest first; review notes appear under `--- REVISION REQUEST (attempt N) ---`.
- `anthropic-api` worker `invoke` returns `RunnerError::Other("unsupported: ...")`.
- Fixtures: real `claude --print --output-format stream-json --verbose --json-schema=...` captures with `--model haiku`, tiny prompts, ≤ 8 paid runs; account email/organization stripped.
- Commands (from `src-tauri`): `cargo test --workspace`; from the repo root: `npx vitest run`, `npx tsc --noEmit`.
- Code comments state the rule, never when or who decided it.

## Plan-level rulings (spec ambiguities)

- **Revise attempts.** Tasks do not carry `attempts` across stages, so the reviewed task is always on attempt 1. "attempts + 1" is counted from the send-back target's last attempt for the item: `n = max(attempts)` over the item's tasks at that stage; the child gets `n + 1`; when `n >= MAX_ATTEMPTS` the item escalates instead. Without this the revise loop never reaches the cap.
- **Revise target.** `on_revise` when set (a team → send back; an escalation id → escalate), else the team whose `on_approve` is the reviewer. No such team, or the target is the pipeline's source (the generator consumes no store) → escalate.
- **Send-back backpressure.** A reviewer's send-back is readmitted to the target store even when it is full (`StoreRepo::readmit`, an uncapped increment): the item is already in the run, and refusing it can wedge the run (the producer waits on the reviewer's store while the reviewer waits on the producer's). The overflow is bounded by the items in flight, and `reserve` admits no new work until the store drains. Gates keep `GateBackpressure` (a human retries).
- **Reject target.** `on_reject` when set, else the pipeline's escalation id (`needs-human` when none declared). The reviewed task itself becomes `needs_human` there (as a gate reject does).
- **Reviewer artifact.** When a reviewer approves without an `artifact`, the reviewed artifact (`parent_artifact`) is forwarded.
- **Producer audit outcome.** Producer and generator results record `verdict:approve` (their item goes forward); reviewer results record their real verdict.
- **Direction note.** With lineage reads there can be several direction notes; the newest one is used.

## Review Focus

1. **The real CLI result line with no `structured_output`** (model gave up after the nudge, `subtype: success`) must be an operational failure, never a silent approve or revise. Pinned in Task 2 with a captured fixture.
2. **A reviewer revise when the producer store is full** must not lose the item, strand it `running`, or wedge the run; the send-back is readmitted past capacity. Pinned in Task 4.
3. **A revise loop** must end in needs-human at the attempts cap, not cycle forever. Pinned in Task 4.
4. **A human comment on the gated parent task** must reach the producer's revised child. Pinned in Task 5.
5. **A comment row with `kind = 'review'`** must not break `list_comments` (the Review store rejects unknown kinds) or the comment rail. Pinned in Tasks 5 and 6.

```rust
fn schema_of<T: schemars::JsonSchema>() -> serde_json::Value {
    let settings = schemars::gen::SchemaSettings::draft07().with(|s| {
        s.option_add_null_type = false;
        s.inline_subschemas = true;
        s.meta_schema = None;
    });
    let root = settings.into_generator().into_root_schema_for::<T>();
    let mut v = serde_json::to_value(root).expect("schema serialises");
    if let Some(o) = v.as_object_mut() { o.remove("title"); o.remove("definitions"); }
    v
}
```
