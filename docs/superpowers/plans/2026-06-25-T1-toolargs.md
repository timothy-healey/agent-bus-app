# T1 — T-ToolArgs: schema-derived tool args + validate-before-dispatch + repair

> **REQUIRED SUB-SKILL:** superpowers:subagent-driven-development. Backlog item **T-ToolArgs**. The CLI-path twin of DS-Schema for the god terminal's agentic loop. First half of the "T" cluster (T2 = N-NativeToolUse builds on the derived schemas).

**Goal:** Every dispatchable OHS tool publishes a **schemars-derived** `input_schema` (no drift from the dispatcher), and the terminal agentic loop **validates a model-emitted `{tool,args}` against that schema before dispatch**, doing a **bounded repair turn** on a miss instead of failing late/silently.

**Architecture:** Per-tool arg structs (`serde::Deserialize` + `schemars::JsonSchema`) owned by each supplier; `tools()` derives `input_schema = schema_for!(ArgStruct)`. The agentic loop validates `args` against the catalog's `input_schema` (a JSON-schema validator) and, on failure, re-prompts on the same `dialogue_id` (≤2 retries, mirroring DS-Schema's `chat_with_repair`). The dispatcher deserializes into the typed arg struct.

## Current state (investigated)
- Production schemas already exist but are HAND-WRITTEN JSON in each supplier's `tools()` (`runtime/api.rs:434`, `review`, `usage_telemetry`) — drift risk vs the `RootDispatcher` `str_arg` parsing.
- `parse_command` / the agentic loop only check `catalog.by_name(name)` (tool NAME) — args pass through UNVALIDATED to `RootDispatcher`, failing late or mis-dispatching.
- DS-Schema's `chat_with_repair` (`pipeline/src/design_session.rs`) is the repair-turn pattern to mirror.

## Tasks (TDD)

- [ ] **Task 1 — Per-tool arg structs (suppliers).** For each dispatchable tool, define a `#[derive(Deserialize, JsonSchema)]` arg struct in its supplier (`runtime`: `InjectTopicArgs{topic, target_repo?}`/`StartRunArgs{topic?}`/`GateArgs{task_id}`/`BrakeOnArgs{reason?}`/`ScaleTeamArgs{team_id}`; `review`: comment/verdict args; `usage_telemetry`: `SetAutoMeterArgs{enabled}` etc.). Add `schemars` to those crates if absent. Tests: each struct round-trips its expected args. Commit.
- [ ] **Task 2 — Derive `input_schema` in `tools()`.** Replace the hand-written `input_schema: json!({...})` in every `tools()` with `schema_for!(ArgStruct)` (serialized to `Value`). Assert the derived schema has the right required/optional props (mirrors DS-Schema's embed test). Commit.
- [ ] **Task 3 — Validate-before-dispatch in the agentic loop.** Add a JSON-schema validator (the `jsonschema` crate) to `conversational_control`. In the agentic loop + `parse_command`, before dispatching a `ToolCallRequest`, validate `args` against `catalog.by_name(tool).input_schema`; on failure produce a specific error (which prop is missing/wrong-typed). For a SLASH command, surface the error to the user (don't dispatch). Tests: valid args pass; missing `task_id` / wrong type is rejected with a specific message. Commit.
- [ ] **Task 4 — Bounded repair turn (agentic loop).** When the MODEL emits a `{tool,args}` block whose args fail validation, re-prompt on the same `dialogue_id` naming the arg error ("re-emit the tool call; `task_id` is required and must be a string"), ≤2 retries (`MAX_REPAIR_RETRIES`), before giving up with a clear turn (mirror `chat_with_repair`). A valid first emit dispatches with no extra call. Tests with a fake chat runner: malformed→repair→valid dispatches; exhausted retries → a clear non-dispatch turn. Commit.
- [ ] **Task 5 — Typed dispatch (RootDispatcher).** `RootDispatcher::dispatch` deserializes `args` into the per-tool arg struct (replacing ad-hoc `str_arg`), so the dispatch path consumes the same type the schema is derived from (single source of truth). Existing dispatch tests stay green. Commit.
