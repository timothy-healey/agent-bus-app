Scheduling bulk-write API — implementation plan

id: T-040
parent_artifact: artifacts/specs/T-040-v1.md
target_repo: ~/splose/splose-monorepo
version: 1

Goal

Expose a bulk-write surface on Scheduling that Imports can call without bypassing domain rules. The surface must be idempotent, batch-friendly, and let callers opt out of side effects per request.

Architecture

One new controller bulk-appointment.controller.ts exposing POST /api/bulk/appointments. The controller validates the batch, then dispatches per-row through the existing AppointmentService.create(). Each record uses a single idempotency key at the batch level; the entire batch is wrapped in a database transaction. On any error, the whole batch is rolled back.

Tasks

Task 1 — controller + endpoint scaffolding

Files:

  • Create: packages/server/src/controllers/bulk-appointment.controller.ts
  • Test: packages/server/src/controllers/bulk-appointment.controller.test.ts

Step 1: Write failing test for empty batch — 400 expected.

describe('POST /api/bulk/appointments', () => {
  it('rejects empty batch', async () => {
    const res = await api.post('/api/bulk/appointments')
      .send({ idempotencyKey: 'k1', records: [] });
    expect(res.status).toBe(400);
  });
});

Step 2: Run, verify it fails. Step 3: implement controller with @CanAccess('imports', 'write') and minimal body.

Task 2 — service-layer dispatch with side-effect opt-outs

Files:

  • Create: packages/server/src/services/bulk-appointment.service.ts
  • Modify: packages/server/src/services/appointment.service.ts — add BulkContext parameter

The endpoint accepts ?skip_welcome=true&skip_reminders=true&skip_analytics=true. The service threads these through to AppointmentService.create() via a new BulkContext object so the existing single-record path stays unchanged.

Task 3 — transactional rollback semantics

On any per-row failure: roll back the entire transaction, return 409 Conflict with the first failed row's index and reason. No partial-batch commits.

Task 4 — idempotency table + uniqueness check

New table bulk_idempotency_keys with (organisationId, key) unique. On request: if the key exists, return the cached response (200 with original payload). If new: insert + execute.

Task 5 — observability

Emit BulkAppointmentsCreated domain event per row, plus a single BulkAppointmentBatchCompleted at the end with row count, elapsed time, and the idempotency key.
