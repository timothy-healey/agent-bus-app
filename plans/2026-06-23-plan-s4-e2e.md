# S4 — Tauri E2E (WebDriver) Harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a complete, correct end-to-end UI test **harness scaffold** that drives the real Tauri app via WebDriver (`tauri-driver` + WebdriverIO), with 1–2 example specs covering a real, LLM-free flow (launch → create a project from a bundled template via the wizard → see it listed) — runnable on Linux/Windows CI, **not** on this macOS dev machine.

**Architecture:** A self-contained `e2e/` directory with its **own** `package.json` (deps install-on-demand, NOT pulled into the root `bun install`/`bun run build`/`bun vitest run`). WebdriverIO is configured with a custom `tauri-driver` service-shim that spawns `tauri-driver` as the WebDriver intermediary and points the session at the built debug binary. The example spec exercises the template-seed wizard path (no live `claude` needed). A runner script builds the debug app and invokes `wdio`. An `e2e/README.md` documents the platform requirement (Linux WebKitWebDriver / Windows Edge WebDriver — **macOS WKWebView is unsupported by `tauri-driver`**) and the exact run steps + CI guidance.

**Tech Stack:** WebdriverIO (`@wdio/cli`, `@wdio/local-runner`, `@wdio/mocha-framework`, `@wdio/spec-reporter`), `tauri-driver` (cargo-installed on the runner), `expect-webdriverio`. All fenced inside `e2e/`.

## Honesty / scope statement (read first)

`tauri-driver` is the WebDriver intermediary Tauri ships. It supports **Linux** (proxying `WebKitWebDriver`, i.e. `webkit2gtk-driver`) and **Windows** (proxying `msedgedriver` against the WebView2 runtime). It does **NOT** support **macOS** — Apple's `WKWebView` exposes no WebDriver automation surface, and `tauri-driver` has no macOS backend. See the Tauri docs ("WebDriver" → "Platform Support"): Windows + Linux only.

This dev machine is **macOS**. Therefore a real E2E session **cannot execute here**, and this plan ships a **scaffold only**:

- The harness (config + service-shim + runner + example specs + deps) is complete and correct for a supported platform.
- It is **excluded** from the default `bun vitest run`, `bun run build`, and the cargo suites. Its deps live in `e2e/package.json` and are **not** installed by the root `bun install`.
- The backlog item is marked **scaffold-only / can't-run-on-macOS / runnable on Linux/Windows CI** — an honest PARTIAL-with-caveats, never a clean "done" implying E2E runs here.
- A `TODO(s4):` note in `e2e/README.md` flags the first live run on a supported platform.

We do **not** run `tauri-driver`, `bun tauri dev`, `bun tauri build`, or any WebDriver session as part of this work (they are blocking GUI commands and would fail/hang on macOS anyway).

## The real flow the example spec drives (LLM-free, OHS-backed)

Grounded in the actual UI (verified in source):

1. App launches → topbar shows the **"No project"** pill (`src/components/Topbar.tsx:42`); main area shows **"No projects yet."** (`src/components/ProjectList.tsx:10-16`).
2. Click **"New project"** (the topbar button, `Topbar.tsx:79-94`) → the wizard dialog opens (`role="dialog"`, `src/wizard/NewProjectWizard.tsx:77`).
3. Fill **Project name** (`aria-label="Project name"`) and **Root path** (`aria-label="Root path"`) — both wired in `NewProjectWizard.tsx:87-88`.
4. Click a **template button** under "Or start from a template" (`NewProjectWizard.tsx:91-107`). This calls the `seed_template_cmd` OHS command (`src-tauri/app/src/lib.rs:563`) — **no live `claude`**, unlike the "Generate" path which needs the LLM kickoff. It seeds the draft and advances to the **Teams** step.
5. Click **Next** through Teams → Prompts → Wiring → **Review** (`NewProjectWizard.tsx:142-143`).
6. On the Review step click **"Create project"** (`src/wizard/ReviewStep.tsx:46`) → calls `create_project_from_draft` (`lib.rs:624`) → hard-validate → write → activate.
7. Wizard closes; the topbar pill now shows the project name; the project is listed (`ProjectList.tsx:18-32`, fed by `workspace_list_projects`, `lib.rs:1076`).

This is a real OHS-backed flow through Pipeline Authoring (seed template + create-from-draft) and Workspace (list projects) — it does not distort any context boundary and needs no network/LLM.

The template path is chosen deliberately over "Generate" precisely because Generate requires a live `claude` subprocess (the LLM Chat ACL kickoff), which can't run headless — the same honesty constraint that governs the rest of this repo's E2E story.

## Task 4: WebdriverIO config wired for `tauri-driver`

**Files:**
- Create: `e2e/wdio.conf.ts`

- [ ] **Step 1: Create `e2e/wdio.conf.ts`**

This is the heart of the harness. It:
- spawns `tauri-driver` before the session and kills it after (WebdriverIO `onPrepare`/`onComplete` hooks);
- points the single capability at the built **debug** Tauri binary via `tauri:options.application`;
- uses Mocha + the spec reporter; targets `localhost:4444` (tauri-driver's default port).

```ts
import { spawn, spawnSync, type ChildProcess } from "node:child_process";
import path from "node:path";
import os from "node:os";

// The built DEBUG binary. `cargo build` (no --release) under src-tauri/ emits it here.
// productName "agent-bus-app" (src-tauri/app/tauri.conf.json).
const BIN_NAME = os.platform() === "win32" ? "agent-bus-app.exe" : "agent-bus-app";
const APP_BINARY = path.resolve(
  __dirname,
  "..",
  "src-tauri",
  "target",
  "debug",
  BIN_NAME,
);

let tauriDriver: ChildProcess | undefined;

export const config: WebdriverIO.Config = {
  runner: "local",
  tsConfigPath: path.resolve(__dirname, "tsconfig.json"),

  specs: ["./specs/**/*.e2e.ts"],
  maxInstances: 1, // a desktop app: one window, serial specs.

  // tauri-driver listens on 4444 and proxies to the native WebDriver.
  hostname: "127.0.0.1",
  port: 4444,
  path: "/",

  capabilities: [
    {
      // tauri-driver reads tauri:options to launch the app binary.
      "tauri:options": {
        application: APP_BINARY,
      },
      // Required placeholder; tauri-driver fills in the real browser cap per-platform.
      browserName: "wry",
    } as WebdriverIO.Capabilities,
  ],

  logLevel: "info",
  bail: 0,
  waitforTimeout: 10_000,
  connectionRetryTimeout: 120_000,
  connectionRetryCount: 3,

  framework: "mocha",
  reporters: ["spec"],
  mochaOpts: {
    ui: "bdd",
    timeout: 120_000, // first launch + template seed can be slow on cold CI.
  },

  // Spawn tauri-driver as the WebDriver intermediary before the session.
  onPrepare: () => {
    if (os.platform() === "darwin") {
      throw new Error(
        "S4: tauri-driver does not support macOS (WKWebView has no WebDriver). " +
          "Run this harness on Linux (WebKitWebDriver) or Windows (Edge WebDriver). " +
          "See e2e/README.md.",
      );
    }
    // Fail early with a clear message if tauri-driver isn't installed.
    const probe = spawnSync("tauri-driver", ["--help"], { stdio: "ignore" });
    if (probe.error) {
      throw new Error(
        "S4: `tauri-driver` not found on PATH. Install it with " +
          "`cargo install tauri-driver --locked` and the platform WebDriver deps " +
          "(Linux: webkit2gtk-driver + xvfb; Windows: msedgedriver). See e2e/README.md.",
      );
    }
    tauriDriver = spawn("tauri-driver", [], {
      stdio: [null, process.stdout, process.stderr],
    });
  },

  onComplete: () => {
    tauriDriver?.kill();
  },
};
```

```ts
import { browser, $, $$, expect } from "@wdio/globals";
import os from "node:os";
import { sel } from "../helpers/selectors.js";

// The headline E2E flow (LLM-free): launch -> New project -> fill basics ->
// seed from a bundled template (no live `claude`) -> Next through the steps ->
// Create project -> see it listed and active in the topbar.
describe("agent-bus-app: create a project via the wizard (template seed)", () => {
  const projectName = `E2E ${Date.now()}`;
  // A real, existing directory the workspace can root the project under.
  const rootPath = os.tmpdir();

  it("creates a project from a template and lists it", async () => {
    // 1. Open the wizard.
    await $(sel.newProjectButton).click();
    await expect($(sel.wizardDialog)).toBeDisplayed();

    // 2. Fill basics.
    await $(sel.projectNameInput).setValue(projectName);
    await $(sel.rootPathInput).setValue(rootPath);

    // 3. Seed from the FIRST bundled template (no LLM kickoff). The template
    //    buttons live under "Or start from a template" (NewProjectWizard.tsx:95).
    //    They are the buttons after the disabled "Generate" button; we select by
    //    waiting for at least one template button to appear, then click it.
    const templateButtons = await $$(
      '//div[contains(., "Or start from a template")]//button',
    );
    await expect(templateButtons.length).toBeGreaterThan(0);
    await templateButtons[0].click();

    // 4. Advance Teams -> Prompts -> Wiring -> Review.
    for (let i = 0; i < 3; i++) {
      const next = await $(sel.nextButton);
      await next.waitForClickable();
      await next.click();
    }

    // 5. Create.
    const create = await $(sel.createProjectButton);
    await create.waitForClickable();
    await create.click();

    // 6. The wizard closes and the project is listed + active in the topbar.
    await expect($(sel.wizardDialog)).not.toBeDisplayed();
    await expect($(`*=${projectName}`)).toBeExisting();
  });
});
```

Note for the implementer/operator: if the template picker renders differently than the XPath above expects (e.g. zero bundled templates in a build), fall back to the "Generate" path is **NOT** acceptable on a headless runner (needs live `claude`). Instead, add a `data-testid` to the template buttons in `NewProjectWizard.tsx` and select by that — but that is a UI change, deferred to the live-run task (`TODO(s4)`), not done in this scaffold pass.

```bash
#!/usr/bin/env bash
# S4: build the debug Tauri app, then run the WebDriver E2E suite.
# Linux/Windows(WSL/git-bash) only — tauri-driver does NOT support macOS.
set -euo pipefail

cd "$(dirname "$0")"

OS="$(uname -s 2>/dev/null || echo unknown)"
case "$OS" in
  Darwin)
    echo "ERROR: tauri-driver does not support macOS (WKWebView has no WebDriver)." >&2
    echo "Run this on Linux (webkit2gtk-driver) or Windows (msedgedriver). See README.md." >&2
    exit 2
    ;;
esac

if ! command -v tauri-driver >/dev/null 2>&1; then
  echo "ERROR: tauri-driver not found. Install: cargo install tauri-driver --locked" >&2
  echo "Plus platform WebDriver deps (Linux: webkit2gtk-driver, xvfb). See README.md." >&2
  exit 3
fi

echo "==> Building the debug Tauri binary (src-tauri/) ..."
( cd ../src-tauri && cargo build )

echo "==> Installing e2e deps (if needed) ..."
if [ ! -d node_modules ]; then
  if command -v bun >/dev/null 2>&1; then bun install; else npm install; fi
fi

echo "==> Running WebdriverIO E2E ..."
# On a headless Linux CI, wrap with xvfb-run:  xvfb-run -a ./run-e2e.sh
if command -v bun >/dev/null 2>&1; then
  bun run test:e2e
else
  npm run test:e2e
fi
```
